诸神愚戏 · 全站 UI 美化与神性特效升级计划书
================================================================
版本：v1.0
日期：2026-09-17
范围：整站前端视觉（含个人面板、天赋页、馆主后台），纯叠加式美化，不改动业务逻辑与数据结构
对齐主题：诸神愚戏 / 祈愿试炼神谕留存地 —— 暗金·命途·神谕·愚戏
目标地址：https://loelv.github.io/fog-dungeon-ranking/


一、背景与目标
----------------------------------------------------------------
现有站点（单页应用，GitHub Pages）已完成功能层建设，视觉体系为「暗金 + 六命途配色」，
组件统一、信息密度较高，但整体偏"静态信息面板"，缺乏游戏化的仪式感与反馈特效。

本轮目标：
1. 全站统一一轮视觉美化，让界面更"贴合诸神愚戏"的神话/神谕质感；
2. 个人面板、天赋页重点增强：卡片渲染、携带槽边框、品阶光效；
3. 抽卡（牵引天赋）加入仪式化特效：抽取、翻牌、品阶揭晓、十连总览；
4. 增加"专属元素"：命途纹样、神性符文、金砂光尘、边框饰纹等，形成独特辨识度；
5. 全程遵守：不改变布局与功能、纯叠加、可一键关闭、尊重省电/无障碍模式。

已落地基础（P0）：
- assets/gods-theme.css：全站神性主题增强层（金砂星尘、分节标题符文下划线、
  卡片四角纹饰、按钮神谕流光、头部光带、面板入场淡升、滚动条/选区/焦点环美化）。
- assets/js/gods-theme.js：氛围层与卡片角饰注入，MutationObserver 自动覆盖动态卡片，
  提供 window.__godsTheme.destroy() 卸载。
- index.html：已挂载上述两个文件（版本号 v=20260917-godstheme1）。

三、设计原则（所有阶段共同遵守）
----------------------------------------------------------------
1. 纯叠加：只加装饰层与样式，不改 DOM 结构语义、不改 JS 业务逻辑。
2. 可关闭：整站可通过 <html data-gods-theme="off"> 关闭；单项特效提供独立类开关。
3. 性能优先：动画只用 transform / opacity；氛围层 pointer-events:none；避免大面积 filter 与重排。
4. 无障碍：@media (prefers-reduced-motion: reduce) 下自动降级为静态。
5. 移动端：延续现有 .profile-mobile-section 等响应式规则，特效在小屏降级或精简。
6. 版本号：每次改动更新对应 ?v= 版本号，确保 GitHub Pages 刷新缓存。
7. 命名空间：新增样式统一以 gt- 前缀或 .gods- 前缀，避免与既有类冲突。
8. 发布流程：因本地仓库 .git 疑似损坏，统一在 /mnt/work/repo（克隆）内提交并推送 origin/main。


四、分阶段路线图
----------------------------------------------------------------

■ P0 主题基础层（已完成）
- 交付：gods-theme.css / gods-theme.js + 首页挂载。
- 验收：首页、详情、神碑三界面生效且布局完好（已实测通过）。

■ P1 天赋页渲染美化 + 携带槽边框（重点）
目标：天赋卡与携带槽具备品阶识别度、悬浮质感与"神性封缄"边框。
改动点（新增到 gods-theme.css，纯叠加）：
1. 品阶边框系统 .talent-card.rank-*：
   - 以现有 rank-B（金）/rank-C（蓝）为基准，补充/统一各品阶描边与内辉光：
     C=青蓝、B=鎏金、A=紫电、S=熔金红、EX/专属=红金双色（专属槽专用）。
   - 手法：border-color + inset box-shadow + 顶部 1px 高光，保持原有背景不覆盖。
2. 角饰：给 .talent-card / .talent-slot-card 复用 .gods-cornered（由 gods-theme.js 注入）。
3. 携带槽边框：.talent-slot-card
   - 已携带：实线描边 + 命途色外发光 + 右上角"封缄"小印（::after 符文）。
   - 空槽 .empty：虚线描边 + 呼吸微光，暗示"可嵌入"。
   - 锁定 .pending：低饱和 + 斜纹遮罩。
   - 专属槽：红金渐变描边 + 缓慢流光（conic-gradient 旋转描边）。
4. 悬停：卡片上浮 1-2px、辉光增强、名称字号轻微提升（不改布局尺寸，用 transform）。
5. 仓库/溢出列表：.talent-log-item 悬停高亮，`.talent-rule-strip span` 顶部符文点缀。
验收：个人面板 → 天赋页，各品阶边框/光效可区分；携带/空/锁定/专属四态清晰；不改变槽位尺寸与点击区域。

■ P2 抽卡（牵引天赋）特效（重点）
目标：把"牵引一枚 / 启十连谕"升级为有仪式感的抽取流程。
改动点：
1. 抽取过渡：点击后按钮进入 talentDrawInFlight 状态时，在结果区 .talent-result-grid
   外层加 .gt-draw-veil 遮罩，呈现"神谕漩涡/星轨收敛"（CSS 动画，2 段：聚拢→绽放）。
2. 翻牌揭晓：结果卡 .talent-card 逐张延迟入场（stagger），由暗到亮 + 轻微 3D 翻转；
   品阶越高，揭晓时的光爆与粒子越强（C 微弱 / B 明显 / S·EX 强 + 屏幕金芒闪）。
3. 品阶横幅：抽取完成后，用 tierSummary 内容在主视觉区短暂展示"本次牵引品阶"横幅。
4. 十连总览：'ten' 时先快速流星序列，再一次性展示 10 张结果卡 + 汇总。
5. 音画可选：预留静音/动效开关（复用 visualEffectsEnabled 语义）。
技术注意：
- 不阻塞 drawTalentUI 的既有逻辑与 await 流程；特效仅为 UI 包装层，
  在结果渲染完成后基于 DOM 存在性触发（MutationObserver 监听 .talent-result-grid 变化）。
- 动画统一在 .gt-* 命名空间，结束后移除临时类，避免残留影响后续抽取。
验收：单抽/十连均有过渡→揭晓→品阶反馈；重复抽取不残留动画类；禁用动效时直接静态展示。

■ P3 个人面板整体美化
目标：让"档案 / 天赋 / 消息"三区与战斗面板更成体系。
改动点：
1. 面板容器 .profile-panel：顶部加入命途色渐变标题带 + 角落符文（.gods-cornered）。
2. 战斗面板（CLASS_HEALTH_RULES / renderProfileBattlePanel 输出）：
   血条/属性条加发光填充与数值脉冲；分类图标加轻微浮动。
3. 档案信息卡：键值行加左侧金色刻度线；头像/称号徽记加呼吸神光。
4. 标签页切换：加"神谕切换"横扫光效（复用 .path-nav-btn 增强）。
5. 消息/日志列表：未读项加微弱脉冲点，悬停高亮。
验收：个人面板各分区视觉统一、层级清晰，滚动/切换流畅，移动端布局不破。

■ P4 馆主后台 + 全站收尾
目标：后台保持"庄重神庭"质感，同时全站统一。
改动点：
1. .admin-panel：深色鎏金边框 + 顶部"馆主"铭牌光效；表格行斑马纹与悬停高亮。
2. 全站表格 tbody 行：悬停高亮（已在 P0 提供基础）。
3. 全站空状态/加载：加入神谕旋转符印（loading 指示），替代单调文字。
4. 全局收尾：统一 .section-title、.btn、卡片入场节奏，检查 6 大命途配色一致性。
验收：后台与前台风格一致又各有侧重；全站无遗漏界面。


五、技术规范
----------------------------------------------------------------
- 文件：样式集中扩展在 assets/gods-theme.css；行为扩展在 assets/js/gods-theme.js。
- 命名：新增一律 gt- / gods- 前缀。
- 动画：仅 transform/opacity/box-shadow/background-position；单次时长 200-700ms；
  长循环动画（氛围层）≥ 90s 且 GPU 合成。
- 降级：prefers-reduced-motion 关闭所有非必要动画；data-gods-theme="off" 关闭整层。
- 开关粒度（建议）：data-gods-theme="off" 全局；.gt-no-draw-effect 关闭抽卡特效；
  .gt-no-slot-border 关闭携带槽边框。
- 兼容：保留对旧类名（rank-B/rank-C 等）的兼容，新增品阶为增量样式。

七、风险与回滚
----------------------------------------------------------------
- 风险1：品阶边框样式与既有 rank-* 冲突 → 采用增量覆盖 + 命名空间，逐品阶核对。
- 风险2：抽卡特效阻塞抽取流程 → 特效与逻辑解耦，仅监听结果 DOM，不介入 await。
- 风险3：动态渲染卡片未加角饰 → 已由 gods-theme.js 的 MutationObserver 兜底。
- 风险4：移动端性能 → 小屏自动精简动画数量与时长。
- 回滚：任一层可通过 data-gods-theme="off" 或删除对应 <link>/<script> 立即失效，不改业务。


八、优先级建议
----------------------------------------------------------------
建议按 P1 → P2 → P3 → P4 顺序推进：
- P1、P2 是你最关心的"天赋携带边框 + 抽卡特效"，改动集中在天赋页，闭环快、可见度高；
- P3 个人面板体量最大，放在特效机制稳定后做，收益最直观；
- P4 后台与全站收尾放最后，统一收口。


附：本计划书对应的落地改动，可逐阶段实施；每阶段完成后单独推送，便于你可视化验收与回退。
